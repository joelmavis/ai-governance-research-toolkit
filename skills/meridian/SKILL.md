# Meridian

Meridian 是一项情报雷达技能：发现变化，而不是堆新闻。它从高质量来源中筛选少量、可行动的研究信号，并将新闻线索转化为可继续研究的问题。

## 报告边界与固定格式

- 每日雷达以 Markdown 交付，并在开头标明“截至北京时间 YYYY-MM-DD 07:00”。
- 默认捕捉基准时间前的过去 24 小时；工作日晨报遇周一时，覆盖上一个工作日结束后至报告基准时间的动态，避免遗漏周末信号。
- 每日固定输出三条信号。优先选择 P1 与 P2；如不足三条，可补入与范围相关、来源可靠的 P3，并明确说明它为何是背景信号、为何尚不构成重大变化。
- 每条至少提供一个可访问来源链接。政策状态、监管规则、数字与关键事实优先使用官方一手来源。
- 每日结尾固定输出“本日判断”：将可确认事实与基于事实的推论分开书写，不把推论写成既成结论。

## 工作方式

1. 扫描 [来源清单](sources/source-list.md) 中与请求时间范围相关的动态。
2. 以事件而不是报道去重；同一政策的多篇报道只构成一个候选信号。
3. 判断其是否带来政策、标准、战略、依赖关系、基础设施、企业治理实践或关键研究理解上的变化。
4. 对重要媒体线索尽量补充一手来源；无法获得时，明确说明来源层级和限制。
5. 依照 [每日模板](templates/daily-radar.md) 固定输出三个信号：优先 P1 和最有价值的 P2；不足时以相关、可靠的 P3 补足，并说明其背景性质。
6. 每周使用 [周报模板](templates/weekly-radar.md) 汇总五个信号、共同变化、研究问题和内容候选。

## 判断规则

- 热度不等于重要性。普通产品发布、重复新闻和无实质变化的讲话默认降级。
- 每个核心信号必须说明“发生了什么”“为什么重要”“所属研究方向”“来源”和五选一建议动作。
- 建议动作只能为：`忽略`、`保存`、`快速研究`、`专题研究`、`内容选题`。
- P1 是可能改变研究判断或值得进一步研究的重要变化；P2 值得保存但暂不行动；P3 是有参考价值的背景信息，不能被包装成 P1 或 P2。
- 主动保留反向信号，例如政策退坡、项目失败、成员国分歧、企业抵制或技术依赖加深。
- 可以使用“这可能意味着”，不得归因给任何用户或写成最终趋势结论。

## 来源纪律

优先顺序为：官方一手来源、国际组织/学术机构/智库、权威媒体、企业官方、研究者账号、社交媒体线索。X 等平台只能作为发现入口；重要事实尽量回到原始文件。

记录原始链接、发布日期、访问日期与必要补充来源。若未能确认原始来源，明确写出该限制，不将转载表述成一手事实。

## 边界

v1.0 不自动发 X、不写公众号、不推送通知、不宣布长期趋势成立、不建立复杂数据库，也不做 24 小时实时监控或大规模关键词抓取。

运行前使用 `scripts/validate_radar.py` 验证成稿的信号数量、优先级、研究方向、来源与建议动作；交付前修正结构性错误。
