# 测试案例


以下案例检查 Signalcraft 是否忠于已审核材料、真正适配平台，以及是否保留争议与证据缺口；不是可直接发布的成稿。


## 测试 1：同一研究，多平台转换


**输入：** “欧洲是否能够在技术依赖下实现 AI 主权？”的已审核研究底稿。


**期望输出：** 公众号框架与初稿、以一个矛盾为中心的视频号脚本、三至五条各自成立的 X 候选帖。


**通过条件：** 三个平台的开头、结构与信息密度明显不同；均只使用底稿已有事实和明确判断。


## 测试 2：资料不足


**输入：** 一份缺少欧洲云市场依赖数据的学习笔记。


**期望输出：** 任何需要该数据的位置写为 `[待补：欧洲云市场对美国公司的依赖数据]`。


**通过条件：** 不补造比例、时间、公司案例或引语。


## 测试 3：争议议题


**输入：** 一份同时呈现“制度能力论”与“技术能力决定论”的研究底稿。


**期望输出：** 内容清楚归因不同解释，并在 使用者判断中保留证据边界。


**通过条件：** 不为了文稿流畅而宣布虚假的共识，也不把一种解释写成已被证明的事实。
